# Codex isolation flags versus user skills: practice plan

## Source and decision

- Source report: `research/agent/agent-knowhow-codex-ignore-config-user-skills-20260815-0504.md`
- Reader problem: a CI, evaluation, or automation maintainer wants checked-in prompts and instructions to be the only model-visible task inputs while using `codex exec --ignore-user-config --ignore-rules` with existing authenticated Codex access.
- Promised decision: determine whether those two flags alone justify calling a Codex CLI 0.147.0 invocation skill-hermetic, and stop using that description if an instruction-only skill under a disposable user home remains explicitly invocable.
- Likely article type: configuration-harness.
- Mode: `boundary`.
- Provider: Codex only. Claude and product comparison are excluded because they cannot change this Codex-specific decision.

## Claim and registered alternatives

The falsifiable claim is that Codex CLI 0.147.0 still discovers and explicitly invokes a skill placed only at `$HOME/.agents/skills/ambient-probe/SKILL.md` when both `--ignore-user-config` and `--ignore-rules` are present. A matched empty-home probe must return `{"status":"unavailable","value":""}`, while the treatment must return `{"status":"loaded","value":"<hidden random marker>"}`. The marker is generated by the adapter, appears before invocation only in the treatment skill body, and is absent from the common prompt, schema, command arguments, filenames, empty-home control, and model/effort settings.

The pre-registered expected outcome is `claim-supported`: the control contains no marker and the treatment returns the exact hidden marker. The competing decisive outcome is `not-reproduced`: both probes reach a clean completion boundary, the control fails closed, and the treatment also returns the exact unavailable object with no marker. That outcome changes the recommendation to a version-scoped non-reproduction on 0.147.0; it does not support the warning as an observed fact. Any wrong marker, control false positive, non-schema result, tool event, incomplete or failed turn, version mismatch, inventory change, marker leak, or other unregistered shape is inconclusive and fails the run without retry.

The practical decision supported by the expected evidence is narrow: the two flags control `config.toml` and execpolicy rules but must not be described as a skill-hermetic boundary. A separate controlled home/catalog or explicit skill filter is required when ambient skills must be absent. The competing result supports only the recorded 0.147.0 location and invocation boundary, not a universal clean-context guarantee.

## Fixture and practical mapping

No existing fixture can vary `HOME`, retain a distinct authenticated `CODEX_HOME`, install one treatment-only skill, preserve a hidden-marker oracle, and compare matched control/treatment results without distorting its own claim. Create the smallest self-contained fixture at `fixtures/agent-practice/codex-ignore-config-user-skills/`:

- `schema.json`: dependency-free two-field result schema; it contains no marker.
- `ambient-skill-wrapper.mjs`: runner adapter that validates all outer controls, creates two fresh empty homes and workspaces, creates the treatment skill, launches two bounded child runs, records normalized evidence, and removes only its case-local runtime directory.
- `preflight-codex.mjs`: executable offline fake CLI used for a complete two-probe rehearsal with zero model calls.
- `verify.mjs`: deterministic Node verifier with an objective exit status and a registered observation marker.

The fixture requires only the already-present Node.js runtime and installed Codex CLI. It uses no dependency installation, browser, login flow, secret, symlink, daemon, source checkout, production state, or external service other than the normal Codex model endpoint during the later live run. The empty control home models a clean runner; the treatment home models a developer or self-hosted runner with one personal skill; the hidden marker models full skill-body consumption; and unchanged empty workspaces plus zero tool events separate prompt-context discovery from tool or filesystem effects.

## Authoritative case and execution

The manifest is authoritative and declares one runner case, `matched-home-skill-boundary`, because one fixture adapter can perform and compare the two necessary matched invocations without duplicating setup or spending on extra cases. It uses provider `codex`, no guidance overlay, no model override, no effort override, and fixture-wrapper execution with `environment: inherit`. The adapter is essential: the stock runner supplies one case root and one inherited process environment, but the claim requires two isolated `HOME` values while authentication remains under the original `CODEX_HOME`.

The executable fixture-relative wrapper is `ambient-skill-wrapper.mjs`; the executable offline fake preflight CLI is `preflight-codex.mjs`. Both paths, the schema, and verifier are protected. The runner's v2 execution block—not a prose-only launch override—selects the wrapper, fake CLI, and inherited environment. No environment or CLI launch override is required or permitted when running the manifest.

The exact common prompt is:

> Explicitly use $ambient-probe and follow it. Use no tools, commands, web search, MCP, hooks, plugins, or file operations. Return exactly one JSON object. If the named skill is available, return status `loaded` and the value it instructs; otherwise return status `unavailable` and an empty value.

The outer runner supplies approval `never`, `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, `--skip-git-repo-check`, JSONL, `-o`, the case root, and `sandbox_workspace_write.network_access=false`. The wrapper rejects any missing or changed control, rejects model and effort overrides, switches each child to `--sandbox read-only`, changes `-C` only to its fresh empty workspace, changes `-o` only to its case-local final file, and adds the protected output schema. Each child receives the same prompt. Live children receive a disposable `HOME` and the inherited authenticated `CODEX_HOME`; credential-bearing environment variables are removed rather than forwarded. If authentication depends only on such a variable rather than the normal Codex home, the later run stops inconclusively.

## Offline preflight boundary

Before any authenticated experiment call, the runner invokes the wrapper against `preflight-codex.mjs`. The wrapper's preflight child environment contains only an allowlisted set of path, locale, terminal, and platform-runtime names plus disposable `HOME`, fake case-local `CODEX_HOME`, and `AGENT_PRACTICE_PREFLIGHT=1`. The allowlist explicitly tolerates harmless macOS runtime injection such as `__CF_USER_TEXT_ENCODING`, plus named XPC and locale variables, while the fake CLI independently rejects every unknown name and every credential-bearing name. The fake supports only `--version` and the two expected exec shapes; it rejects model/effort overrides, requires approval `never`, read-only sandboxing, both ignore flags, ephemeral mode, output schema, and network false. It reads only the disposable treatment skill to synthesize the registered response.

Preflight receives no credential, performs no authentication, network, model, or paid request, and never invokes the real Codex child through the fixture. A failed preflight stops the runner before the two live model calls. The runner's own local authentication-status prerequisite occurs outside fixture preflight and must not be described as a model call or fixture evidence.

## Verification and changed-path boundary

Run `node verify.mjs` from the disposable case root. It checks the exact CLI version, schema and marker hashes, common controls, two successful process outcomes, exactly one completion and no failure per child, zero command/file/MCP/web events, empty workspaces, exact home inventories, aligned JSONL/final evidence, control marker absence, and one of the two registered treatment outcomes. It creates `verification.txt` containing `AMBIENT_USER_SKILL_BOUNDARY_OBSERVED`; this marker means the boundary produced a decisive registered result, not that the claim was necessarily supported. `probe-result.json` retains `claim-supported` or `not-reproduced`.

Protected paths are exactly `schema.json`, `ambient-skill-wrapper.mjs`, `preflight-codex.mjs`, and `verify.mjs`. Allowed changes are exactly `control-events.jsonl`, `control-final.json`, `treatment-events.jsonl`, `treatment-final.json`, `probe-result.json`, and `verification.txt`. The wrapper deletes its `.ambient-skill-runtime` before runner diffing. Any other fixture-tree change, any protected digest change, any symlink, or any home/workspace inventory drift fails.

## Run, safety, cost, and evidence limits

- Run count: one provider and one manifest case; one complete fake preflight containing two offline fake execs; then exactly two live model invocations, control followed by treatment. No automatic retry.
- Timeout: 300 seconds for the wrapper case; each child is capped at 120 seconds and the local version check at 30 seconds.
- Network: manifest `network: false` is Codex workspace-sandbox enforcement for task tools, not a block on the CLI's provider transport. No Claude host branch exists. The fake preflight is fully offline.
- Credentials: use only already-established normal Codex authentication. Do not log in, read, copy, list, hash, print, relocate, or modify credential files. Do not forward credential-bearing environment names to either fake or live child. Authentication or version failure is a stop condition.
- Cost: at most two live model requests, no model or effort override, no retry, no benchmark, and no price or latency claim. Preflight has zero model and paid requests.
- Isolation: both probes use fresh non-Git empty workspaces, read-only sandboxing, no writable additions, no tools, no task-side network, no MCP, plugin, hook, rule, project guidance, Git operation, dependency installation, browser, or production system.
- Redaction: retain the inert generated marker, fixture-relative inventories, hashes, structured final values, JSONL events, counts, exit facts, and registered observation. Do not retain environment values, credential material, unrelated home contents, or private absolute paths.
- Cleanup: the runner removes its temporary root and preserves redacted evidence under ignored `logs/agent/`. The wrapper removes only its explicitly named case-local runtime directory. Git state is not changed.

The later runner command is fixed and needs no launch override:

```sh
node scripts/agent-practice/run-experiment.mjs practice/agent/agent-practice-codex-ignore-config-user-skills-20260815-0504.json
```

This experiment cannot establish implicit skill activation, skill precedence, malicious-skill behavior, privilege escalation, other Codex versions or platforms, all skill locations, or hermeticity for plugins, hooks, MCP, memory, managed configuration, system skills, authentication, or other home-derived inputs. Its article value is the narrower current-version decision rule backed by a hidden-marker control and a copyable, bounded harness.
