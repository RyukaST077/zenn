## 上位候補の詳細

### 1. TS6時代のtsconfigをTypeScript 7に通したら、既定値の変更で何がエラーになったか

#### 概要

2026-07-08 にGAした TypeScript 7.0 は Go 製ネイティブ実装で、公称8〜12倍の型チェック速度。ただし速度以上に効いてくるのが**既定値と対応範囲の変更**で、`strict` が既定ON、`module` が `esnext`、`rootDir` が `./`、`types` が自動探索から `[]` に変わり、`baseUrl` は削除、`target: es5` と `moduleResolution: node` は廃止されている。「速くなった」記事は多いが、「旧設定のまま通したら具体的に何行エラーが出て、どの設定をどう書き換えたか」の実ログは薄い。そこを埋める。

#### なぜ今よさそうか

- GAから3週間以内の一次情報で、国内の移行需要がこれから立ち上がる
- 破壊的変更が箇条書きで公式に列挙されている＝検証項目を設計しやすい
- 「JS API がない」「Vue/Svelte/Astro などの埋め込み言語は TS7 未対応」という**移行を止める条件**が明示されており、記事の結論部分が書きやすい

#### 新人が検証しやすい理由

npm install だけで完結し、ブラウザもDockerもクラウドも要らない。TS6 で通る小さなプロジェクトを自作し、`tsc` を差し替えて出るエラーを写すだけで一次情報になる。

#### 想定読者

- 手元のプロジェクトを TS7 に上げるか判断したい人
- `types: []` や `baseUrl` 削除の影響がピンとこない人

#### タイトル案

1. TypeScript 7に上げたら、tsconfigの既定値変更で何行エラーが出たか数えてみた

### 4. CSS`contrast-color()`と、自分で書いた輝度計算の白黒判定を突き合わせてみた

#### 概要

`contrast-color()` は背景色を渡すと白か黒の読みやすい方を返す CSS 関数で、2026年4月に主要4ブラウザが揃って Baseline newly available になった。これまで JS の相対輝度計算（WCAG の式）で白黒を決めていた処理を1関数に置き換えられるかを、**同じ色セットで判定結果を突き合わせて**確認する。

- Baseline 到達直後で、実装に載せてよいかの判断材料が求められている

- Playwright スクリーンショットで記事映えする

#### 新人が検証しやすい理由

HTML/CSS と数十行のJSだけ。ビルドもサーバも最小で済む。

#### 想定読者

- ボタンやタグの文字色を背景色から自動で決めている人
- アクセシビリティ対応を CSS 側に寄せたい人

#### 検証でやること

- 色を数十色（グレースケール階段＋境界付近の中間色＋彩度の高い色）用意

6. 全体スウォッチのスクリーンショットを保存
