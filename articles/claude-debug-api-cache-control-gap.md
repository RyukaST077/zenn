## 症状: `--debug api --debug-file`で`cache_control`を探したが1件も出てこない

プロジェクトのサブエージェント (`.claude/agents/*.md`) に `experimental: cacheTtl: 1h` を設定した場合、Claude Code のドキュメントには「サブスクリプションの使用量クレジットで動いているセッションでは `1h` が無視される」という記載がある。これを自分のアカウント・自分の CLI バージョンで確かめたいとき、ドキュメントやコミュニティの議論が示唆する定番の手段は `claude --debug api --debug-file <path>` で API リクエストを覗き、`cache_control` ブロックに `ttl` が入っているか、`anthropic-beta: extended-cache-ttl-2025-04-11` ヘッダーが付いているかを見ることだ。

Claude Code 2.1.248 でこれを実際にやってみると、期待した検証はできなかった。ログ自体は空でも壊れてもいない。ただし、そこに `cache_control` という文字列は一度も現れない。

この記事が確認できたのはこの1点に尽きる。「`cacheTtl: 1h` がサブスクリプション課金で本当に無視されるかどうか」自体は、今回の実行では判定できていない。判定できなかった理由そのものが、同じ検証手順を踏もうとしている読者にとって価値がある情報になる。

## 実行した検証

- CLI: `claude` `2.1.248 (Claude Code)`
- 手法: `experimental.cacheTtl: 1h` を設定したプロジェクトサブエージェントを、非対話 (`-p`) モードから `Task` ツール経由で1回呼び出し、`--debug api --debug-file` で書き出したログと `stream-json` イベントを解析する1ケースの実験(fixture-wrapper 経由)。
- 事前登録した判定基準: ログに `cache_control` ブロックが見つかり、`ttl` フィールドと `anthropic-beta` ヘッダーの有無を確認できた場合のみ `gated`(無視されている)/`not-gated`(効いている)のどちらかを判定する。1件も `cache_control` が見つからなければ `unregistered`(未判定)として扱う、という設計。
- 実行結果: プロセス自体は正常終了 (`agent_exit_code: 0`)、実際に課金された1回の呼び出し (`total_cost_usd` 約0.065ドル、`live_model_calls: 1`)。だが検証スクリプトは `verifier_exit_code: 1` で失敗し、観測は `unregistered`(未判定)だった。

## 何が起きていたか: ログの中身とタイミングの2つの想定外

### 1. `debug-api.log`にリクエスト本文が入っていない

出力された `debug-api.log`(210行)には `/v1/messages` へのリクエストを示す `[API REQUEST]` 行が3本あった。メインセッションからの呼び出し1本、`source=sdk` の呼び出し1本、そしてディスパッチされたサブエージェントからの呼び出し (`source=agent:custom:cache-ttl-probe`) 1本だ(その後2ターン目の `source=sdk` 行がもう1本続く)。

ところが、この4行すべてを含むファイル全体を正規表現 `/"cache_control"\s*:\s*\{[^}]*\}/g` で走査しても、マッチは0件だった。ファイルの中身を直接確認しても、記録されているのは `[API:timing]`、`[Stall]`、`attribution header x-anthropic-billing-header: ...` といった、タイムスタンプ・クライアントリクエストID・課金アトリビューションヘッダーなどの運用系メタ情報だけで、リクエストやレスポンスの JSON ボディそのものは一切含まれていなかった。

同じ正規表現ロジックを、あらかじめ用意した合成データ(オフラインのプリフライトフィクスチャ)に対して走らせたときは、`cache_control` ブロックを1件正しく検出し `gated` と正しく分類できている。つまり解析ロジック自体に不具合はない。実際のCLIが `--debug api --debug-file` で書き出すログの中身に、そもそも探しているフィールドが存在しなかった、というのがここでの一次的な事実だ。

**これが意味すること**: Claude Code 2.1.248 において、`--debug api --debug-file` は「APIリクエストが飛んだこと」と「そのタイミング・課金情報」は記録するが、「そのリクエストの中身」は記録しない。ログの見た目は充実している(行数もあり、リクエストの発生も分かる)ため、「機能が発火していない」と早合点しやすいが、正しくは「そのログには元々その情報が出力される設計になっていない」。

### 2. `-p`モードからの`Task`ツール呼び出しは非同期で、2回目の`init`イベントを生む

検証スクリプトは「セッション中に `system:init` イベントは1回だけ出るはず」という前提で1ターンの解析をするよう作られていた。だが実際に流れてきた `stream-json` イベント(21行)を見ると、`system:init` が2回(0番目と16番目)、しかも別々の `session_id` を伴って出現していた。

その間には次のような流れがある: `Task` ツールの呼び出しがバックグラウンドタスクとして非同期にディスパッチされ(6〜7番目)、ツール結果として「Async agent launched successfully」というテキストが返り(8番目)、アシスタントは一旦中間的な「ok」を返す(9番目)。その後、非同期タスクの完了通知(`task_notification`/`task_updated`, `status: completed`, 11〜12番目)を経て、新しいエンジンターン・新しいセッションが始まり(16〜19番目)、最終的な「ok」が返る。

**これが意味すること**: 非対話 (`-p`) モードから `Task` ツールでサブエージェントを呼ぶと、単一の同期的な tool_use/tool_result のやり取りにはならず、非同期のバックグラウンドタスクとして扱われ、その完了に伴ってセッションが実質的にもう1周する。1ターン・1initを前提にした解析スクリプトは、この時点で(たとえリクエスト本文が取れていたとしても)最初のアサーションで失敗していた可能性が高い。実際、今回の検証もこの `init_event_count === 1` という前提を満たせずに、それより先に失敗している。

## 結局、`cacheTtl: 1h`はサブスクリプション課金で無視されるのか

分からない。今回の実行はこの問いに答える証拠を得られなかった。ドキュメントが述べている「使用量クレジットのセッションでは `1h` が無視される」という記述自体はAnthropicの一次情報として存在するが、それを自分のリクエストで裏取りする、という今回の試みは成立しなかった。取得したログにその判定に必要なフィールドが存在しなかったからだ。

このセッションが本当にサブスクリプションの使用量クレジットで動いていたかどうかも、`rate_limit_event` に `rateLimitType: "five_hour"` と `overageStatus: "rejected"` / `overageDisabledReason: "org_level_disabled"` が記録されており、クレジット課金と矛盾しない状況証拠ではあるものの、ハードな確認手段では検証していない。

## 読者が今すぐできること

- `claude --debug api --debug-file` を「リクエストボディを見るためのツール」として使わない。2.1.248時点でこのフラグが実際に出すのは、タイミング・クライアントリクエストID・課金アトリビューションヘッダーなどの運用メタデータであり、`cache_control` / `ttl` / `anthropic-beta` ヘッダーの中身は記録されない。
- `cache_control` や `ttl` の実際のリクエスト形状を確認したいなら、この記事の方法では確認できなかったと理解した上で、ローカルプロキシ経由でのキャプチャなど別の手段を検討する必要がある(今回の実行ではその方法自体は試していない)。
- `-p` 非対話モードから `Task` ツールでサブエージェントを呼ぶ挙動を自前のスクリプトで解析する場合、1ターン・1 `system:init` を前提にしないこと。非同期ディスパッチによって、完了待ちの間に2つ目の `system:init` を伴う新しいセッションが挟まることがある。

## 再現条件とスコープ

- 実行環境: `claude` `2.1.248 (Claude Code)`、認証状態はCLIのステータスコマンドで確認(認証情報ファイル自体は読んでいない)。
- サンプル数: 1アカウント・1 CLIバージョンでの1回の実課金呼び出し(コスト約0.065ドル)。オフラインのプリフライト(合成データによる自己テスト)も1回。
- この記事の結論は、この1サンプル・1バージョンの範囲に限定される。異なる `--debug` サブコマンド、別バージョンのCLI、APIキー課金のセッション、プロキシ経由のキャプチャについては、いずれも検証していない。
- 非同期 `Task` ディスパッチの挙動は、今回の観測に対して「フィクスチャ側の前提が実際の挙動を見込んでいなかった」というだけであり、バグや退行として報告しているものではない。
