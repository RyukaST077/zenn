Claude Codeを`claude -p`（非対話モード）で使っていて、こういう経験はないでしょうか。

1. あるディレクトリで作業して会話を終える
2. 別のディレクトリに`cd`する（別プロジェクトの作業や、一時的な検証ディレクトリなど）
3. 続きのつもりで`claude -p --continue`を実行する
4. さっきの会話とは関係ない、新しい会話が始まってしまう

これは`--continue`が「今いるディレクトリに紐づいた直前の会話」しか拾わないために起きます。この記事では、Claude Code `2.1.270`の実機（認証済みの既存CLIセッション）で`--continue` / `--resume <id>` / `--fork-session` / `--no-session-persistence`の4つを実際に動かし、それぞれが何をするかを`session_id`とファイルの増減で確認します。読み終えると、「今のディレクトリの続きでよいか」「特定の会話にどこからでも戻りたいか」「元の会話を壊さず枝分かれしたいか」「記録を残したくないか」という状況ごとに、どのフラグを使えばよいか判断できるようになります。

対象読者は、`claude -p`を実行したことがあり、`cd`でのディレクトリ移動や`--output-format json`のJSON出力を読んだことがある人を想定します。追加のツールやアカウント登録は不要ですが、手元で再現するには認証済みの`claude` CLIが必要です（この記事の検証も、新規ログインやAPIキーなしで、既存の認証済みセッションのまま行っています）。

## 会話はどこに保存されているか

Claude Codeは`-p`で実行するたびに、その会話を`~/.claude/projects/<ディレクトリ名を変換した文字列>/<session-id>.jsonl`というファイルに保存します。ディレクトリごとにサブフォルダが分かれるため、「別ディレクトリからの`--continue`が効かない」という挙動は、探す場所（フォルダ）が違うために起きています。

`session_id`は各会話に振られるIDで、`--output-format json`を付けて実行すると出力のJSON内で確認できます。

```bash
# ディレクトリAで実行
cd /tmp/dir-a
claude -p --output-format json "こんにちは"
```

出力のJSONに`session_id`フィールドが含まれます。以降の検証は、すべてこの`session_id`を起点にしています。

## 検証1: `--continue`はディレクトリに紐づく

ディレクトリAで会話を始めたあと、別のディレクトリBで`--continue`を実行すると、Aの会話は拾われるでしょうか。

```bash
# ディレクトリBで実行（Aとは別のディレクトリ）
cd /tmp/dir-b
claude -p --continue --output-format json "続きです"
```

今回の実行では、ディレクトリAで得た`session_id`（`bb0188db-...`）と、ディレクトリBで`--continue`を実行して得た`session_id`（`19a0b2c3-...`）が異なるIDになりました。つまりディレクトリBの`--continue`は、ディレクトリAの会話を拾わず、無関係な新しい会話として扱われています。`--continue`は「今いるディレクトリで直前に保存された会話」だけを探す、ディレクトリ紐づけの機能だとわかります。

## 検証2: `--resume <id>`はディレクトリを問わない

ディレクトリをまたいで同じ会話に戻りたい場合は、`session_id`を直接指定する`--resume`を使います。

```bash
# ディレクトリBで実行（Aで得たsession_idを指定）
cd /tmp/dir-b
claude -p --resume <ディレクトリAで得たsession_id> --output-format json "続きです"
```

この実行では、指定した`session_id`（`764daa15-7aaf-4666-9318-d818eb3ec158`）が、実行前後で変わらずそのまま使われました。ディレクトリAとは別のディレクトリBから実行しても、同じ会話に戻れています。ディレクトリ名を覚えていなくても`session_id`さえ控えておけば、どこからでもその会話を再開できるということです。

## 検証3: `--fork-session`は元の会話を壊さずに枝分かれする

同じ会話から別方向を試したいが、元の会話は残しておきたい、という場面では`--fork-session`を`--resume`と組み合わせます。

```bash
claude -p --resume <session-id> --fork-session --output-format json "別の方向を試す"
```

この実行では、新しい`session_id`（`6991e632-...`、元は`c8e50ef0-...`）が発行され、新しい`.jsonl`ファイルが作られました。そして実行前と実行後で、元の`.jsonl`ファイルのハッシュ値を比較したところ両者は一致しており、元ファイルはバイト単位で変化していませんでした。`--fork-session`は元の会話ファイルをコピーしたうえで新しいIDを振る形で枝分かれし、元の会話は読み取り専用のまま残る、と確認できます。

## 検証4: `--no-session-persistence`は保存そのものを止める

一時的な確認だけで、あとから会話ファイルを残したくない場合は`--no-session-persistence`を使います。

```bash
# 新しい一時ディレクトリで実行
claude -p --no-session-persistence --output-format json "一回だけ確認したい"
```

この実行後、そのディレクトリに対応する`~/.claude/projects/`配下のフォルダを確認したところ、`.jsonl`ファイルは1つも作られていませんでした。他の3つの検証が「どのファイルに戻るか／どうファイルを枝分かれさせるか」を扱っていたのに対し、これは「そもそもファイルを作らない」という別の分岐です。

## 状況別の決定表

4つの検証結果をまとめると、次の決定表になります。

| 状況 | 使うフラグ |
|---|---|
| 今のディレクトリで作業を続けたい | `--continue` |
| 別のディレクトリから、あるいはIDを控えてある会話に戻りたい | `--resume <session-id>` |
| 元の会話を壊さずに別方向を試したい | `--resume <session-id> --fork-session` |
| この実行の記録を残したくない | `--no-session-persistence` |

判断の起点は「今いるディレクトリで見えなくなった会話をどう扱いたいか」です。`--continue`で見つからなければ、まず`session_id`を控えてあるか確認し、`--resume`に切り替えるのが最初の一手になります。

## この検証の前提と限界

- 検証はすべてClaude Code `2.1.270`、1台のマシン上で、各ケース1回ずつ実行した結果です。他のバージョンやOSでも同じ挙動になるとは確認していません。
- 検証には既存の認証済み`claude`セッションを使い、新規ログインやAPIキーの追加は行っていません。認証情報の値自体は読み取っていません。
- 実行時に`network: false`という設定を使っていますが、これはこの検証を動かした外側の仕組み（Codexのサンドボックス）に対する制限であり、Claude本体の通信をOSレベルで遮断するものではありません。この記事は「ファイルと`session_id`がどう変化するか」の確認であり、ネットワーク遮断や権限分離の安全境界を検証したものではない点に注意してください。
- `--continue`を実行したディレクトリに、そもそも過去の会話が一つも無かった場合に何が起きるか（新規会話が始まるのか、エラーになるのか）は今回の検証では区別していません。

## まとめ

`--continue`が見つけられないのは「ディレクトリが違うから」であり、バグではありません。会話に戻れなくて困ったら、その会話の`session_id`を控えて`--resume <id>`に切り替える、元を残したまま試したい分岐は`--fork-session`、記録を残したくない一回限りの実行は`--no-session-persistence`、という4択で判断できます。
